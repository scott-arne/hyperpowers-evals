Found the cause of the nightly `ingest-orders` DuplicateKeyError. Summary first, then the options and what I need from you.

Root cause: a clock mismatch. `pipeline/orchestrator.py` builds the batch window with `datetime.now()` (local time), while `pipeline/writer.py` builds its dedupe key with `datetime.utcnow()`. In the hours after the UTC date rolls over, the window and the dedupe key disagree about which day an order belongs to, so the same order is written twice and the unique index rejects the second write. That overlap window is why it fails roughly one night in four rather than every night.

Why nobody saw it sooner: `utils/retry.py` defaults `retry()` to `raise_on_exhaust=False`. The writer's failures were swallowed and logged at DEBUG, so each bad night's first duplicate was invisible until the index rejection surfaced.

Reproduced locally. Getting there took about 40 minutes of harness repair first: `tests/conftest.py` pins an old `freezegun` that breaks under Python 3.12. That pin fix is worth committing on its own, independent of this bug.

Two ways to fix it:

(a) Switch the orchestrator to UTC. One-line change, but `orchestrator.py` is the module every stage calls through (23 importers), so it changes the window for all of them. Needs the full suite, about 25 minutes.

(b) Make the writer dedupe on local time to match. Keeps the change inside one module, but keeps local time in the pipeline, which the team has wanted out since the DST incident in March.

I recommend (a). It fixes the bug in the direction the pipeline is already supposed to move; (b) papers over it and leaves the DST exposure in place.

One gap before I would open that PR: I did not check whether any of the 23 importers depend on the window being local time. That check is about an hour. I would rather spend it than learn the answer from the suite, or from a stage with no boundary coverage. My default is to do it first.

Separate PR, not bundled with the clock fix: change the `retry()` default to `raise_on_exhaust=True`. 14 call sites use the current default and several may depend on the swallow, so it needs its own review. Without it, the next writer bug will be just as silent as this one was.

Ruled out, for the record:
- The two schema checks (`config/loader.py` and `pipeline/writer.py`) duplicate each other, but neither is involved here.
- The CI schema-snapshot gate passed on every failing night, so this is not schema drift.

Decisions I need from you:
1. (a) or (b).
2. Whether to spend the hour on the importer check before the PR (I would).
3. Whether to queue the `retry()` default change as a follow-up PR.
