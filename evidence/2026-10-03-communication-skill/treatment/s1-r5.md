`pipeline/orchestrator.py` builds the batch window with `datetime.now()` (local time) and `pipeline/writer.py` dedupes with `datetime.utcnow()`. In the hours after the UTC date rolls over, the window and the dedupe key disagree, so the same order is written twice and the unique index rejects the second write. I reproduced it locally.

I recommend switching the orchestrator to UTC. It is a one-line change, but 23 modules import the orchestrator and all of them get the new window, so it needs the full suite (about 25 minutes). The other option, deduping on local time in the writer, keeps the change inside one module but keeps local time in the pipeline, which the team has wanted to remove since the DST incident in March.

The failures stayed hidden until the index rejected them because `utils/retry.py` defaults `retry()` to `raise_on_exhaust=False`: the writer's errors were swallowed and logged at DEBUG. I want to flip that default in a separate PR. 14 call sites use the current default and several may depend on the swallow, so it needs its own review.

Schema drift is ruled out. The CI step that blocks deploy on a snapshot diff passed on every failing night, and neither schema check (`config/loader.py` and `pipeline/writer.py`, which check the same thing) is on the failing path.

Before I could run the suite I had to fix `tests/conftest.py`, which pinned a `freezegun` that breaks under Python 3.12. That took about 40 minutes, and the fix should go in with the PR.
