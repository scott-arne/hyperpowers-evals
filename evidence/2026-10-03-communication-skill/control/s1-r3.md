Done with the `ingest-orders` investigation. Root cause found and reproduced; summary first, details after.

Root cause: a clock mismatch between two modules. `pipeline/orchestrator.py` builds the batch window with `datetime.now()` (local time), while `pipeline/writer.py` dedupes with `datetime.utcnow()`. In the hours after the UTC date rolls over, the window and the dedupe key disagree, so the same order is written twice and the unique index rejects the second write. That matches the roughly 1-in-4 failure rate: it only bites when a batch straddles the rollover.

Why nobody saw it earlier: `utils/retry.py` defaults `retry()` to `raise_on_exhaust=False`. The writer's failures were swallowed and logged at DEBUG, so the first duplicate was invisible until the index rejected it.

Reproduced locally. Getting there took about 40 minutes because `tests/conftest.py` pins an old `freezegun` that breaks on Python 3.12; the suite would not run until I fixed that. That fix is in my working tree and should land regardless of what we do about the bug.

Fix options:

(a) Switch the orchestrator to UTC. One-line change, but `pipeline/orchestrator.py` is the module every stage calls through (23 importers), so it changes the window for all of them. Needs the full suite (~25 min).

(b) Make the writer dedupe on local time to match. Stays inside one module, but keeps local time in the pipeline, which the team has wanted gone since the DST incident in March.

Recommendation: (a). It fixes the bug in the direction the team already wants to go. Caveat: I have not checked whether any of the 23 importers depend on the window being local time. That is about an hour of work, and I would do it before merging, not after.

Separate PR: flip the `retry()` default to `raise_on_exhaust=True`. 14 call sites use the current default and several may depend on the swallow, so this needs its own review and should not ride along with the clock fix.

- The CI schema-snapshot gate passed on every failing night; it is not a factor.
