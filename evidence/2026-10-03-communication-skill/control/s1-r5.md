Found the cause of the nightly ingest-orders DuplicateKeyError. Short version: a clock mismatch between the orchestrator and the writer. I recommend switching the orchestrator to UTC, with one check I have not done yet before merging.

Root cause
  pipeline/orchestrator.py builds the batch window with datetime.now() (local time).
  pipeline/writer.py builds the dedupe key with datetime.utcnow().
  In the hours after the UTC date rolls over, the window and the key disagree, so the
  same order is written twice and the unique index rejects the second write. That is
  consistent with it failing only some nights rather than every night.

Reproduced locally. Note that the suite would not run under Python 3.12 at first:
tests/conftest.py pinned an old freezegun. I fixed the pin to get the suite running
(about 40 of the 120 minutes went there). That change is in my working tree and
should probably land on its own.

Why nobody saw it earlier
  utils/retry.py defaults retry() to raise_on_exhaust=False, so the writer's failures
  were swallowed and logged at DEBUG. The first visible symptom was the index rejection.

Fix options
  (a) Switch the orchestrator to UTC. One-line change, but orchestrator.py is imported
      by 23 modules, so it changes the window for all of them. Needs the full suite
      (about 25 minutes).
  (b) Make the writer dedupe on local time to match. Keeps the change inside one
      module, but keeps local time in the pipeline, which the team has wanted out
      since the DST incident in March.

Recommendation: (a). It fixes the bug in the direction the team already wants to go;
(b) leaves another DST-shaped problem in place.

Gap before merging (a): I have not checked whether any of the 23 importers depend on
the window being local time. That check is about an hour. I would do it before the
change rather than find out from the suite or from production. Want me to go ahead?

Separate follow-up, not for this PR: change the retry() default to
raise_on_exhaust=True. 14 call sites use the current default and several may depend on
the swallow, so it needs its own review and PR.
